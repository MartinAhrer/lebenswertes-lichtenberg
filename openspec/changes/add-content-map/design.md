# Design

## Context

The site has six content pages, three sample news posts and an error page (see `add-hugo-static-site`). Content comes from three kinds of source:

- **Front matter**, such as the Startseite's `heroCaption`, `heroLead`, `heroImage` and `heroButtons`.
- **Markdown body text**, including the `feature-grid` shortcode for the Startseite cards.
- **Site configuration**, such as the site name in `languages.de.toml` and the menus in `menus.de.toml`.

Several blocks are generated by the theme. These include the recent-post cards, which show a post's title, date, reading time, a 30-word summary and its image if it has one, the "Neue Beiträge" heading, and the footer line `© <year>` with "Erstellt mit Hugo & Blowfish".

The README already has a short table of page files. No `docs/` directory exists yet, and Hugo builds only from `content/`, `assets/`, `layouts/` and the theme.

## Goals / Non-Goals

**Goals:**

- One place where an author can see a page, point to a block and know what to supply.
- Sketches that read as drafts, so nobody mistakes them for the final design.
- A structure that makes keeping the map current cheap.

**Non-Goals:**

- Pixel-accurate mock-ups or screenshots. They go stale with every theme update and suggest a precision the map doesn't need.
- Phone-specific sketches. The text notes where the phone layout differs, for example the menu collapsing and cards stacking.
- Documenting how to use Git or edit Markdown, which the README already covers.

## Decisions

### 1. A folder in `docs/` with one Markdown guide and one SVG per page type

```
docs/inhaltskarte/
  README.md            # the map: introduction, one section per sketch
  gemeinsam.svg        # header, banner, footer, background
  startseite.svg
  aktuelles.svg
  beitrag.svg
  textseite.svg        # Über uns, Kontakt, Impressum, Datenschutz
  fehlerseite.svg
```

`README.md` opens automatically when someone browses the folder on GitHub, and every Markdown preview renders the SVGs with `![…](startseite.svg)`. Being outside `content/`, nothing in the folder is published.

- **Alternative: a hidden page in `content/` with `build: never`.** Rejected because the map would sit beside real content, and one wrong setting would publish it.
- **Alternative: one large SVG for the whole site.** Rejected because it is hard to read on a laptop screen and hard to edit.
- **Alternative: ASCII sketches or Mermaid diagrams.** Rejected because neither looks like a page layout, and Mermaid isn't rendered in every editor.
- **Alternative: a shareable web page or PDF.** Rejected in favour of the repository, as the user chose, so the map changes together with the layout.

### 2. Hand-drawn SVG sketches with a rough-line filter

Each sketch is a hand-written SVG about 800 units wide, drawn as a wireframe:

- **Lines and fonts:** boxes, image placeholders (a box with a cross) and wavy lines for text. An `feTurbulence` + `feDisplacementMap` filter roughens the lines. Text uses a system handwriting font stack (`"Bradley Hand", "Segoe Print", "Comic Sans MS", cursive`) with no web fonts.
- **Colours:** a white "paper" background with dark ink, so the sketch reads the same in light and dark mode. Block IDs sit in an accent-coloured circle, and fixed or automatic blocks are drawn in grey.
- **Shared elements:** sketches other than `gemeinsam.svg` show the header and footer as grey stubs labelled `G`, so shared blocks are numbered only once. Their badges are grey, so each orange badge appears on exactly one sketch.

- **Alternative: screenshots of the real site with numbered overlays.** Rejected for the reasons in Non-Goals, and because placeholder text in screenshots confuses authors.
- **Alternative: a drawing tool export (Excalidraw, Figma).** Rejected because it adds a tool and a source file to keep in sync. Plain SVG can be edited in any text editor and diffs cleanly.

### 3. Block IDs: page letter plus number

| Prefix | Sketch |
| --- | --- |
| `G` | Gemeinsame Elemente |
| `S` | Startseite |
| `A` | Aktuelles |
| `B` | Beitrag |
| `T` | Textseite |
| `F` | Fehlerseite |

Numbers follow reading order, top to bottom and left to right, so `S3` is the third block on the Startseite. When a block is removed, its ID isn't reused, so content an author has already labelled with an ID stays unambiguous.

### 4. One table per sketch, with a fixed set of columns

Each sketch section shows the image, then a table:

| ID | Baustein | Wofür | Umfang | Wo eintragen |
| --- | --- | --- | --- | --- |
| S2 | Schlagzeile | … | max. 40 Zeichen | `content/_index.md`, Feld `title` |

Automatic or fixed blocks have *automatisch* or *fest eingestellt* in the "Umfang" column. Their "Wo eintragen" column names the source, for example "aus den Beiträgen: `title`, `date`, Textanfang". After the tables, a short section covers images for all blocks: rights and credit in the Impressum's Bildnachweis, file formats, and where alternative text goes.

- **Alternative: one subsection per block.** Rejected because about 35 blocks would make the map long. A table can be scanned beside its sketch.

### 5. Measure limits on the built site

Limits are recommendations that keep a block tidy at 375 pixels and at desktop width. They were measured by putting German test text of increasing length into each block of the rendered pages, at both widths. No tested length caused horizontal page scrolling, so each limit is the longest text that keeps the block compact:

| Block | Limit | Measured reason |
| --- | --- | --- |
| Startseite headline (`title`) | 30 characters | 3 lines on a phone; 40 needs 4 |
| Startseite caption (`heroCaption`) | 40 characters | 2 lines on a phone |
| Startseite lead text (`heroLead`) | 150 characters | 6 lines on a phone, 3 on desktop |
| Button and card link label | 20 characters | one line at both widths |
| Card title / text (`feature`) | 25 / 150 characters | title on one line on a phone |
| Post title | 60 characters | 3 lines on a card |
| Post summary (card preview) | 150 characters in `summary` | the card cuts the preview after 5 lines |
| Aktuelles and text page titles | 25 characters | 2 lines on a phone |
| Subheadings | 50 characters | 2 lines on a phone |
| Photos | landscape, at least 1920 × 1080 px, JPEG, at most 2 MB | the theme scales the Startseite photo to 1920 px and page backgrounds to 1200 px wide; the banner crops a 4 : 1 strip from the top |

A single long word can still overflow at phone width. The site already hyphenates headings, so the map advises avoiding very long compound words in button labels and card titles.

### 6. Document the optional post image as a page bundle

Posts are single files now, so they have no image. The theme shows a post's image behind its title and on its card when the post is a folder (`content/aktuelles/<name>/index.md`) with an image named `feature.jpg` next to it. This works with the current configuration. The map documents it as the way to add a post image, together with the `alt` field. No layout changes are needed.

### 7. Keep the map current through the README and an OpenSpec rule

The README's "Editing content" section links to the map, and its page table points to the map for details. A `rules.tasks` entry in `openspec/config.yaml` reminds every future change that adds, removes or moves a block to include a task for updating `docs/inhaltskarte/`.

- **Alternative: an automated check that compares front-matter fields with the map.** Rejected as too much for a site this small. Most blocks aren't front-matter fields, so it would miss most changes anyway.

### 8. Show post details only on news posts

The theme reads each setting as `.Params.showDate | default site.Params.article.showDate`. Because `default` treats `false` as empty, a page can turn these settings on but not off. So `article.showDate`, `showReadingTime` and `showPagination` are off site-wide in `params.toml`, and a `cascade` in `content/aktuelles/_index.md` turns them back on for every news post. New text pages need no extra front matter, and new posts inherit the cascade.

- **Alternative: a site-level `cascade` in `hugo.toml` that lists the text pages.** Rejected because every new text page would have to be added to the list.
- **Alternative: `showDate: false` in each text page.** Rejected because the theme ignores it, as explained above.

## Risks / Trade-offs

- **The map drifts from the site** → The OpenSpec rule and the "kept current" requirement put it in every layout change. Review compares the sketches with the local preview.
- **Rough-line filters render differently between viewers** → Keep the displacement small and the text unfiltered, so labels stay sharp even where the filter isn't supported.
- **The handwriting font is missing on a system** → The stack ends in `cursive`, and the layout leaves room for wider fallback fonts.
- **Limits look stricter than they are** → The map calls them recommendations. Exceeding them doesn't break the build.
- **Authors put rights-encumbered photos in** → The image section requires rights and credit, and points to the Bildnachweis section in the Impressum.

## Migration Plan

Nothing to migrate. Archive `add-hugo-static-site` before this change, because this change adds requirements to the `content-authoring` capability it introduces.
